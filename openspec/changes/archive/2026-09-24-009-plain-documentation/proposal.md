# Proposal

## Why

The user asked to rewrite the documentation and examples in plain English, and to update the constitution to require
that style and to record the lessons from the 0.15.0 release.

The documentation used a terse, literary voice. Sentences inverted their word order for effect, for example "A venue
with an official betting API is placed at by the library." Pages repeated warnings and mixed several topics in one
block. The README put the basic install, the MCP extra, the execution extra and the development install in a single
block. The 0.15.0 release also showed that a locally set secret hid a broken example, so an example that needs a secret
or the network can pass on one machine and fail in a clean build.

This change sets `skip_specs: true`. It changes only the wording of documentation and docstrings, the structure of the
documentation pages, and the constitution. FR-008 forbids any change to library behaviour, the public API or any name.
No function, class, command, option or tool behaves differently, accepts different input or returns different output.
A user of the API, the command line or the MCP server observes no difference, so no capability spec changes.

The constitution amendments are history. They are recorded here and in the design, not as specs.

## What Changes

- Rewrite the README, the user guide pages, the gallery examples and the public docstrings shown in the rendered docs
  in plain English: short, direct sentences in subject, verb, object order, with headings a reader can scan.
- Split the README install section into four subsections: basic install, MCP extra, execution extra, development
  install.
- State each real risk, such as spending real money, once and plainly.
- Keep every code example runnable offline, with sample data, a placeholder or a fake in place of a secret or a live
  request. An example that cannot run offline is removed.
- Amend the constitution: the Writing Style rules require the plain style and forbid the clever, inverted,
  passive-for-effect, idiomatic and defensive style. A new rule requires every code example to run, verified by the
  build. The 0.15.0 release lessons are recorded. The version is bumped and a Sync Impact Report is written.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

None. The change is documentation style only.

## Impact

- Docs: `README.md`, `docs/overview/user_guide/index.md`, `sources.md`, `dataloader.md`, `bettor.md`, `execution.md`,
  the gallery examples under `docs/examples/sources`, `docs/examples/dataloaders`, `docs/examples/modelling` and
  `docs/examples/execution`.
- Code: docstring prose in `src/sportsbet/**/*.py`, with signatures, names and `>>>` doctest blocks and their output
  unchanged.
- Constitution: `openspec/constitution.md` Writing Style rules, the example rule and the release lessons.
- Generated: `docs/generated` is regenerated by the build, never hand-edited.
- Dependencies: none.
- Out of scope: `docs/generated`, the generated changelog, private docstrings that are not rendered, and the rest of the
  constitution body.
- Specification quality checklist: every item passed. The three questions the user raised (scope, how the style is
  checked in review, how examples are proven to run when one needs a secret or the network) were resolved with
  reasonable defaults in the spec's assumptions.
